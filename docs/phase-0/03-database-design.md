# Phase 0 — PostgreSQL Database Design

**Status:** Proposed for approval. No migrations are created in Phase 0.
**Target:** PostgreSQL 16. Use native `uuid`, `timestamptz`, `jsonb`, and check constraints; prefer text checks over native enums to keep migrations simple.

## 1. Design rules

1. Every tenant-scoped table has `tenant_id uuid NOT NULL` and RLS enabled.
2. All IDs are UUIDv4 generated by the application.
3. Timestamps are `timestamptz`; application stores UTC and renders `Africa/Algiers`.
4. Money uses `numeric(14,2)` plus `currency char(3)` (default `DZD`); no float money.
5. Soft delete via `deleted_at timestamptz` on user-visible entities.
6. No sensitive prompt content in logs; prompt text in DB is limited and retention-bounded.

## 2. Entity overview

```text
tenant 1---N tenant_membership N---1 user
tenant 1---N campaign
campaign 1---N content_item
tenant 1---N content_item
tenant 1---N ai_generation_job
tenant 1---N metric_snapshot
tenant 1---N usage_counter
tenant 1---N audit_log
```

## 4. Row Level Security

Every tenant-scoped table gets:

```sql
ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <table> FORCE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON <table>
  USING (tenant_id = current_setting('app.current_tenant_id', true)::uuid)
  WITH CHECK (tenant_id = current_setting('app.current_tenant_id', true)::uuid);
```

The application sets `SET LOCAL app.current_tenant_id = :tenant_id` inside the request transaction. Migration roles bypass RLS explicitly. Integration tests must prove that a valid session from tenant A cannot read tenant B rows even if an application query forgets a filter.

## 5. Migration and lifecycle plan

- Alembic baseline migration creates extensions (`citext`), tables, constraints, indexes, and RLS policies together.
- Migrations are expand-then-contract; no destructive column drops in the same release that stops writing them.
- `ai_generation_jobs.prompt` and `result_body` are retained for 30 days by a scheduled cleanup job (Phase 3), unless the PRD requires longer.
- Daily backups with point-in-time recovery; restore drill before pilot.
- No production data in test environments; deterministic factories only.
