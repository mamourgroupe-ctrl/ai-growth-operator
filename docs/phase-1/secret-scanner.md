# فاحص الأسرار — النطاق والاستثناءات

السكربت: `scripts/check_no_secrets.py`  
الأمر في CI: `python scripts/check_no_secrets.py`  
Issue: #32

## السلوك

- يفحص كل ملفات المستودع النصية افتراضياً، وليس مجلدي التطبيق فقط.
- يُخرج فقط `المسار:رقم_السطر [معرّف_القاعدة]` عند وجود نتيجة. **لا يطبع أبداً القيمة التي طابقت القاعدة**، حتى لا يظهر سر حقيقي في سجلات CI.
- يخرج برمز `0` عند عدم وجود نتائج، وبرمز `1` عند وجود نتائج.
- يمكن تمرير جذر بديل للاختبارات: `python scripts/check_no_secrets.py <path>`.

## القواعد

| معرّف القاعدة | ما تكتشفه |
|---|---|
| `quoted-secret-assignment` | إسناد قيمة نصية مقتبسة إلى اسم حساس مثل `SECRET_KEY` أو `API_KEY` أو `PASSWORD` أو `TOKEN` |
| `credentialed-url` | URL يتضمّن `user:password@host` |
| `private-key-header` | ترويسة مفتاح خاص PEM |
| `aws-access-key-id` | معرّفات مفاتيح AWS من النمط `AKIA...` / `ASIA...` |
| `github-token` | رموز GitHub من النمط `ghp_...` أو `github_pat_...` |

## الاستثناءات عن قصد

| الاستثناء | السبب |
|---|---|
| `.git/`, `.venv/`, `node_modules/`, `.next/`, `__pycache__/` | تبعيات أو بيانات git/مخرجات مولّدة؛ ليست كوداً تابعاً للمشروع وقد تحتوي على ملفات ضخمة أو ثنائية |
| `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `.tox/`, `.turbo/`, `.output/`, `.parcel-cache/`, `.svelte-kit/`, `dist/`, `build/`, `target/` | مجلدات كاش/بناء مولّدة؛ لا تمثّل مصادر يمكن مراجعتها |
| `.env` و`.env.*` عدا `.env.example` | قد تحتوي أسراراً محلية حقيقية؛ الفاحص يتعمّد عدم قراءتها أو عرضها. `.env.example` يُفحص لأنه نموذج بدون قيم سرية |
| اللواحق `.lock`, `.log`, `.pyc`, `.tsbuildinfo` | ملفات قفل/سجلات/بايت كود/كاش TypeScript مولّدة؛ لا تُضاف أسرار تطبيقية إليها يدوياً |
| الملفات غير النصية | لا يمكن فحصها كنص؛ يتم تخطيها عند فشل فك التشفير |
| السطر الذي يحوي `secret-scan-exempt` | استثناء صريح داخل الكود لبيانات اختبار وهمية فقط. **يجب** أن يتبعه سبب بعد علامة النقطتين، ويخضع لمراجعة الـ PR. يُستخدم حالياً لكلمات مرور الاختبار الوهمية في `tests/` |

الملفات التالية تُفحص صراحةً ولا تُستثنى: `.github/workflows/ci.yml`، `scripts/`، `tests/`، `docs/`، `apps/`، `pyproject.toml`، `alembic.ini`، `Makefile`، `.gitignore`، وملفات `.pem`/`.key` النصية.

ترتيب القواعد يجعل النمط الأخص (مثل رمز GitHub) يُسجّل قبل الإسناد العام، حتى لا يُخفى معرّف القاعدة الدقيق.

## لماذا لا يوجد استثناء لـ `package-lock.json`؟

يُفحص كنص عادي؛ محتواه عبارة عن تجزئات وأرقام إصدارات ولا يتطلب استثناءً. تكلفة الفحص مقبولة.

## اختبارات الفاحص

`tests/test_secret_scanner.py` يغطي:

- اكتشاف الإسنادات الحساسة وعناوين URL التي تحوي بيانات دخول وترويسات المفاتيح الخاصة ومعرّفات AWS/GitHub.
- أن الاستثناء الصريح يمنع النتيجة.
- أن المجلدات والملفات المستبعدة لا تُفحص.
- أن النتائج لا تحتوي على قيمة السر.
- أن المستودع الحالي نظيف بحسب الفاحص.
